## 3. Decisions — do not re-litigate

- **No wrapper script.** A `course.sh` was built, then deleted the same day. It passed the
  right folder to `trace backfill`, which **hid the week 3 lesson** before a reader could find
  it, and it taught the wrapper instead of the tools. The commands are the lesson.
- **Every lab step has a Predict beat.** The gap between expectation and record is the content.
- **GitHub needs no separate copy.** The lab page is the GitHub post. Substack and LinkedIn get
  per-week copy in `campaign-v2/week-N/`. Carousels ship as PDF.
- **Art rule: one idea per picture.** Kept from `docs/images/`: `inter-agent-overview`,
  `failure-stack` (caption notes it predates 17 FMs), `same-model-matrix`, `eval-two-trees`,
  `eval-telemetry-writers`, `eval-infra-vs-evidence`, `eval-corpus-kinds`,
  `eval-audit-checklist`. Not used: `architecture_diagram` (too dense, stale table),
  `eval-self-review-cadence` and `hero-linkedin` (about Rick, not the reader).
- **Weeks 4 and 6 stay gated** on ≥30 unaided annotations and one real closed loop.

## 4. Findings the repo did not have

**`trace backfill` hard-coded `backend="crewai"`** (`evals/cli.py`, `_cmd_trace_backfill`) — fixed in §5.
Pointed at `output/runs/`, all 334 traces read `crewai / unknown / failed`; 236 have zero
spans. The 2026-09-15 claim that re-indexing "clears all five floors" came from `minieval.py`,
not from the harness.

**`minieval.py` is also wrong, differently.** It reports `langgraph 219 · unset 113 · crewai 1 ·
claude-agent-sdk 1` and "floors met" — counting `unset` as a backend. Week 3 teaches both.

**Default backfill reproduces the starved harness in 5 s:** 50 traces, 0 spans.

**`finalize()` is called only from the web server and the Claude SDK backend.** 220 of 318
`run.json` files have `completed_at: null`. A `$0` placeholder run shows it in five seconds.

**Adding a check touches six places**, all enforced by tests: registry import,
`_CHECK_SPAN_READS`, `trace_fixtures.py` builder + `ALL_CHECK_IDS`, a sensitivity mutation,
fixtures in `evals/fixtures/traces/` (the dumper writes to `tests/fixtures/traces/` — copy
across), and the Tier A baseline, whose `baseline accept` refuses a dirty tree.

**Taxonomy layers:** 11 harness · 4 model · 1 framework · 1 provider.

## 5. The backfill label fix (same session)

`TraceBuilder.from_workspace` now reads the run record: backend from `run.json` (top level or
`extra`), status from `extra.final_status` or a `complete` phase in `state.json`, and start/end
from `run.json` when a trace has no spans (so a backfill no longer stamps every trace with build
time — the "1.97-second window" in the 2026-09-13 audit). Unrecorded backends become
**`unknown`** (new `BackendName` value) with a warning; unrecorded statuses still default to
`failed`, now with a warning. `trace backfill` passes `backend=None` and gained `--backend` to
force one. Writer side: `ResultsBundle.finalize(backend=...)` fills a missing backend, and the
web server passes it — the web path was why 113 runs had none.

After, on 338 runs: `langgraph 223 · unknown 113 · crewai 1 · claude-agent-sdk 1`;
`complete 209 · failed 129`; 240 with zero spans. 4 builder tests + 1 bundle test added;
`from_workspace` split into `_resolve_clock` / `_resolve_status` to stay under the
150-line function ratchet. Unit suite: 1,614 passed; the one failure was the link guard
seeing untracked files, cleared by the commit.

**Still open:** `failed` conflates "failed" with "never recorded a status". A proper fix
is an `unknown` status, which touches sampling strata and several checks — not done.
