## TL;DR

1. **One boundary does all the work: `Trace`.** Left of it (backend runs) is billed and
   flaky. Right of it (checks, judges, aggregation) is free and deterministic. That

## The gap this closes

The repo already had a decent *measurement* layer, built up over the June/July
comparison work: `evals/fixtures.py` (`EvalResult`, `LLMJudge`, `EnsembleJudge` with
vendor independence and disagreement spread), `evals/metrics.py`, `run_evals.py` with
watchdogs, `guardrails/corpus_metrics.py`.

What was missing was the *methodology* layer — and the list was embarrassing once
written down:

| Gap | Consequence |
|---|---|
| No trace corpus — logs scattered across per-run workspaces | Every analysis started by re-reading raw JSONL by hand |
| Taxonomy written from memory, not coded from traces | No eval linked to any of the ten classes |
| No human labels | No judge TPR/TNR. `metrics.py` already set `judge_provisional = True` — honest, but a standing IOU |
| Judges emit continuous scores vs. thresholds | A gate that moves when you squint at it |
| Judge prompts as inline class constants | Unversioned. A prompt edit silently invalidates every past verdict |
| No CI eval job | Lint/test/web-e2e/integration/security only |
| No replay | Every eval run costs money and is non-reproducible |
| `LLMJudge.check()` returned `passed=False` on error | **Judge timeouts inflated the measured failure rate.** Errors are now `verdict: error`, excluded from denominators |

That last one is the sharpest: for weeks, a flaky judge and a genuinely broken run were
the same number in the output.

## Trace boundary

```
workspace logs  →  Trace corpus  →  open coding (human)
                                 →  axial coding → taxonomy YAML
                                 →  deterministic checks
                                 →  golden labels (human) → judge align/validate
                                 →  SuiteReport → gate
```

Scoring is a pure function of traces plus cached judge verdicts. Nothing right of the
boundary opens a socket — and there's a test that enforces exactly that by monkeypatching
`socket.connect` to raise and running every check against every fixture
(`test_check_purity.py`).

**Checks have to actually discriminate.** `test_check_sensitivity.py` takes each
check's *passing* fixture, mutates it in the specific way the failure mode describes
(strip the `tool_use` spans and leave a fenced code block in the phase output; append
five extra `phase_start` spans; set `listener_self_triggers`), and asserts the check
flips to fail. A check that returns `pass` for everything is a check that passes CI
forever.

**Judges are binary and versioned.** One yes/no question per gating judge, prompt in a
versioned file (`evals/judges/prompts/fm-001-tool-call-omission.v1.md`), verdicts cached
by `prompt_hash`. Continuous `LLMJudge.check()` survives for legacy callers but is
deprecated for gates.

**A judge may only gate after it earns it:** TPR ≥ 0.90, TNR ≥ 0.90, Cohen's κ ≥ 0.70,
n ≥ 100 on a held-out test split. Below that bar, verdicts are advisory and the report
says so. Bias correction is `p = (p̂ + TNR − 1) / (TPR + TNR − 1)`, suppressed when the
denominator ≤ 0.2 rather than reported as a confidently-wrong corrected rate.

**Splits are deterministic and test access is rationed.**

```text
split = "test" if int(sha256(labeling_unit_id)[:8], 16) % 100 < 40 else "dev"
```

`judge align` reads dev only; `judge validate` reads test once per `prompt_hash` and
needs `--allow-retest` for a second look, logged. You cannot iterate a prompt against
the test split by accident.

## Two CI-only bugs, one of them the good kind

**1. Lint and timing (`c4ed6fe`).** Ruff walked the fixture trees; and the 200-trace
purity budget (R5.5: <5s on a laptop) flaked on shared `ubuntu-latest` because
`CHK-listener-self-trigger` re-introspected `AITeamFlow` listeners on every trace.
Cached the introspection, excluded fixtures from ruff, and gave CI a 15s ceiling while
keeping 5s locally — still tight enough that an uncached regression fails, loose enough
that a noisy runner doesn't.

**2. The fixture that only existed on my laptop (`aeabb13`).** A global `logs/` entry in
`.gitignore` swallowed `tests/fixtures/mini_workspace/logs/` — the JSONL inputs the
`TraceBuilder` integration test reads. Locally the files sat there untracked and the
test passed; in CI the workspace had no logs, the builder produced `status: failed`, and
the test failed. Classic **works-on-my-machine via gitignore**: the test wasn't wrong,
its fixture was invisible to everyone but me.

This is FM-010 (`gate_environment_mismatch`) happening to the tooling built to detect
FM-010, on the same day. Filed without irony.

## Deferred on purpose

The whole point of a methodology layer is that it doesn't lie about its own state.
Four things are unfinished, and all four are written down in `tasks.md`,
`EVAL_METHODOLOGY.md`, and `docs/eval-runs/2026-08-16/`:

| Task | What's deferred | Why |
|---|---|---|
| 5.2 | Human open coding on ≥100 live traces | **Human work.** A model labeling its own ground truth makes every downstream number meaningless |
| 7.2 | Live `judge align` (≤ $1.00) | Human-triggered spend; advisory fixtures under `evals/golden/alignment/` carry `eligible_to_gate: false` |
| 9.4 | Flip Tier A off `--warn-only` | Needs a week of green nightlies first |
| 10.2 | Full Tier C live run (≤ $5.00) | Human-triggered spend; run note is pre-written, awaiting real numbers |

So the honest summary is: **the plumbing is real, the ground truth is not yet.** 50
traces backfilled and indexed out of ~315 workspaces; taxonomy examples are synthetic
check fixtures; judges are advisory. The harness measures correctly and currently has
almost nothing true to measure. That's the right order to build it in, but it would be
easy to write a README that hides which half is done.

## Design note

Two rules from this build worth carrying into anything else that scores model output:

1. **Put the boundary where the money is.** Everything that costs a dollar goes on one
   side, everything deterministic on the other, and the artifact between them is
   serializable. Free CI, reproducible reports, and retroactive analysis all fall out of
   that one decision.
2. **A measurement system has to publish its own error bars.** TPR/TNR on the judge,
   Wilson intervals on the rates, `n` on everything, and errors excluded from
   denominators rather than counted as failures. A harness that reports its subject's
   uncertainty but not its own is just a more confident kind of guess.
